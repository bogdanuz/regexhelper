# Тестер — архитектура

Краткое описание инструмента «Тестер» (проверка regex на тестовой строке): назначение, структура кода, интеграция.

---

## Назначение

Пользователь вводит регулярное выражение и тестовый текст. Совпадения подсвечиваются **прямо в поле** тестового текста (как на regex101). Отдельный блок **Match Information** выводит список совпадений (Совпадение N, диапазон индексов, текст) и под каждым — **Группа 1**, **Группа 2**, … с диапазоном и захваченным текстом. Flavor: **Python (emulated)** — поведение приближено к Python/regex101: препроцессинг паттерна (флаг x), сборка флагов (a/u), при глобальном поиске (g) жадные `[\s\S]*` и `[\s\S]+` заменяются на ленивые варианты, чтобы получать несколько неперекрывающихся совпадений. Поддержка других flavor запланирована.

При выделении пользователем фрагмента **тестового текста** (мышью или клавиатурой) в заголовке блока «Совпадения» справа появляется строка **статистики выделения**:  
`Символов всего: N • Без пробелов: M • Пробелов: K`.  
Статистика считается только для выделения внутри поля тестового текста; при снятии выделения или потере фокуса панель скрывается.

### TRUE/FALSE выражения (исключения)

- В панели тестера теперь два поля regex:
  - **Регулярное выражение (TRUE – что ловить)** — основное выражение.
  - **Регулярное выражение (FALSE – что исключить)** — дополнительное выражение-исключение (опционально).
- Поведение:
  - Если заполнен только **TRUE** — тестер работает как раньше: подсветка и список совпадений только по TRUE.
  - Если дополнительно заполнен **FALSE** и паттерн валиден:
    - Считаются совпадения TRUE и FALSE по одному и тому же тестовому тексту.
    - Совпадения TRUE, которые **пересекаются по диапазону символов** с любым совпадением FALSE, считаются исключёнными.
    - В поле тестового текста подсвечиваются **только очищенные совпадения TRUE (после исключения FALSE)**.
    - В блоке совпадений отображаются две секции:
      - **«Совпадения TRUE (после исключения FALSE)»** — итоговый список TRUE-совпадений.
      - **«Совпадения FALSE (исключения)»** — все совпадения FALSE (даже если они никого не «выключили»).
  - Поле **FALSE само по себе не работает**: если TRUE пустой или невалиден, совпадения по FALSE не считаются и не подсвечиваются (показывается только ошибка у паттерна, если он невалиден).

**Флаги:** g, m, u (по умолчанию, как Python на regex101), i, s, x, ascii — в выпадающем списке «Флаги» в шапке панели. В списке есть подсказка: «По умолчанию: g, m, u (как Python на regex101). a и u не совместимы.» Чекбокс «unicode» по умолчанию включён; флаг **u** добавляется в строку флагов только при включённом чекбоксе и при выключенном **a**. При u **\b** и **\w** работают с кириллицей (эмуляция: в JS нативный \b без i только ASCII, поэтому паттерн препроцессится — \b/\B заменяются на Unicode-аналоги).

**Расчёт** выполняется в **Web Worker** с таймаутом 60 с; при превышении — сообщение об ошибке и тост с просьбой упростить паттерн или сократить текст.

### Флаги (кратко)

| Флаг | По умолч. | Назначение |
|------|-----------|------------|
| **g** (global) | да | Искать все совпадения. |
| **m** (multiline) | да | `^` и `$` — начало/конец каждой строки. |
| **u** (unicode) | да | `\w`, `\b`, `\W` по Unicode (кириллица и др.). |
| **i** (insensitive) | нет | Без учёта регистра. |
| **s** (single line) | нет | Точка `.` матчит перевод строки. |
| **x** (extended) | нет | Игнорировать пробелы и комментарии `#` в паттерне. |
| **a** (ascii) | нет | `\w`, `\d`, `\s`, `\b` только ASCII. Несовместим с u. |

В блоке «Совпадения» выводится фактическая строка флагов (например `gmu`).

## Валидация regex и подсветка ошибок

- **Сообщения:** при любой ошибке (нет ответа, Worker, таймаут, синтаксис) в UI показывается одно из двух сообщений: «Неверное регулярное выражение, исправьте ошибку.» (под полем regex) или «Ошибка при проверке регулярного выражения. Попробуйте упростить выражение или обновить страницу.» (Worker/таймаут). Техническое сообщение движка выводится только в консоль браузера.
- **Ошибка только под полем regex:** блок с текстом ошибки отображается только под полем «Регулярное выражение», не под полем тестового текста.
- **Подсветка места ошибки в поле regex:** поле regex имеет оверлей (как поле тестового текста). При ошибке ошибочные символы подсвечиваются красным; поддерживается **несколько позиций одновременно** — пользователь видит все найденные места ошибки.

### Реал-тайм валидация (2026-02-28)

При вводе в поле regex (после debounce 180 ms) выполняется **validatePatternForUI(raw, flagsState)** без запуска воркера. Используется тот же препроцессинг, что и при запуске (флаг x, замена \b/\B на Unicode-границы), и те же флаги. Позиции ошибок в обработанном паттерне **маппятся в исходный (raw)** паттерн, чтобы подсветка в поле соответствовала тому, что видит пользователь. При невалидном паттерне показываются сообщение под полем и подсветка всех `errorIndices`; воркер не запускается. При валидном — подсветка ошибок сбрасывается и запускается расчёт.

### Типы обнаруживаемых ошибок

Проверки выполняются **до** вызова `new RegExp(...)` (в `matchRunner.js` и в `validatePatternForUI`); при выбросе из RegExp позиция дополнительно извлекается из сообщения движка.

| Тип | Описание |
|-----|----------|
| **Скобки** | Баланс `( )` с учётом `[...]` и экранирования: лишняя `)`, незакрытая `(`. |
| **Ведущий/конечный \|** | `\|...` или `...\|` — пустая альтернация в начале или конце. |
| **Пустая альтернация \|\|** | Оба символа `\|` подсвечиваются. |
| **Лишняя `}`** | `}` не входящая в валидный квантификатор `{n}`, `{n,}` или `{n,m}` (учёт `[...]` и экранирования). Функция **getMisplacedBraceIndices(p)**. |
| **Сообщение движка** | При выбросе из `new RegExp(...)` — индекс из сообщения или повторная проверка скобок/фигур. |

Результат — массив `errorIndices` для подсветки; в runMatch и validatePatternForUI индексы дедуплицируются и сортируются.

## Поле тестового текста: оверлей и размеры

- **Высота по умолчанию:** поле «Тестовый текст» имеет `rows="18"`, `min-height: 480px`, `max-height: 1200px` (примерно в 3 раза больше прежнего).
- **Слой подсветки:** размеры оверлея задаются в JS по `clientWidth`/`clientHeight` textarea, чтобы ширина контента и переносы строк совпадали; обновление при инициализации, после каждого результата (`finish`) и при изменении размера (ResizeObserver). У оверлея `overflow: hidden`, скролл только у textarea; позиция скролла синхронизируется при прокрутке и после обновления контента. Пустые совпадения (длина 0) не рисуются — убирается артефакт подсветки в пустом поле. Для совпадения положения подсветки и каретки браузера в оверлее используется тот же моноширинный шрифт и `line-height`, отключены принудительные разрывы слов (`overflow-wrap` / `word-break`), чтобы переносы строк совпадали с реальным `textarea`.
- **Обрезка по границам:** обёртка поля имеет `overflow: hidden`, `min-height: 480px`, `flex-shrink: 0`, чтобы контент не выходил за границы и блок не сжимался во flex-раскладке.

### Статистика выделения тестового текста (selection stats)

- В заголовке блока «Совпадения» (`tester-match-info-header`) справа расположен элемент `#tester-selection-stats`; по умолчанию он скрыт (`hidden`).
- При наличии выделения внутри поля тестового текста (`#tester-test-input`) считается:
  - **Символов всего** — длина выделения (`selected.length`), включая переводы строк, табы, неразрывные пробелы и т.д.
  - **Без пробелов** — длина строки после удаления **только обычных пробелов** `' '` (переводы строк и другие пробельные символы не выкидываются).
  - **Пробелов** — количество обычных пробелов `' '` во всём выделенном фрагменте.
- Формат отображения: `Символов всего: 12 345 • Без пробелов: 12 000 • Пробелов: 345` (числа форматируются через `Intl.NumberFormat('ru-RU')`).
- Статистика обновляется при событиях `select`, `keyup`, `mouseup` на textarea; при `blur` и при отсутствии выделения панель скрывается.

## Структура кода

- **tools/tester/app.js** — точка входа: `initTester()`, `resetTesterPanel()`.
- **tools/tester/logic/patternPreprocess.js** — флаг x: удаление пробелов и комментариев вне `[...]`. **applyExtendedFlag(pattern)** возвращает обработанную строку; **applyExtendedFlagWithMap(pattern)** возвращает `{ pattern, rawByProcessed }` (маппинг позиций обработанного паттерна в исходный для реал-тайм подсветки ошибок).
- **tools/tester/logic/flagsBuilder.js** — сборка строки флагов для RegExp. Флаг **u** добавляется только при включённом чекбоксе «unicode» (state.u) и при выключенном a; по умолчанию в UI чекбокс u включён. Приоритет a над u.
- **tools/tester/logic/matchRunner.js** — препроцессинг (при g — замена `[\s\S]*`/`[\s\S]+` на ленивые; при u без i — замена \b/\B на Unicode-границы); **getBracketErrorIndices(p)**, **getMisplacedBraceIndices(p)** (лишняя `}`), **getErrorIndicesFromMessage(msg, p)**; создание RegExp; сбор совпадений с группами и indices (флаг d). Возврат `{ matches }` или `{ error, errorIndices }`. **validatePatternForUI(raw, flagsState)** — валидация с тем же препроцессингом и маппингом позиций в raw; возвращает `{ valid: true }` или `{ valid: false, error, errorIndices }` (индексы в исходном паттерне). **filterMatchesByFalse(trueMatches, falseMatches)** — helper, который исключает из списка TRUE-совпадений те, чьи диапазоны символов пересекаются с любым совпадением FALSE (используется в UI для реализации TRUE/FALSE логики).
- **tools/tester/worker/matchWorker.js** — Web Worker: получает `patternTrue`, опционально `patternFalse`, `flagsState`, `str`; вызывает `runMatch` для TRUE и (при необходимости) для FALSE, возвращает `{ trueResult, falseResult }` или одиночный результат (для обратной совместимости, когда FALSE не используется).
- **tools/tester/ui/testerUI.js** — UI: два поля regex (TRUE/FALSE) с оверлеем подсветки ошибок только для TRUE, поле тестового текста с оверлеем подсветки совпадений, флаги, блок Match Information, **строка статистики выделения**; debounce 180 ms; в **schedule()** перед запуском воркера вызывается **validatePatternForUI** для TRUE и (при необходимости) для FALSE — при невалидном TRUE воркер не запускается, при невалидном FALSE воркер запускается только с TRUE. После получения результатов применяется `filterMatchesByFalse`, в тексте подсвечиваются только очищенные TRUE-совпадения, в блоке совпадений выводятся секции для TRUE и FALSE.
- **tools/tester/css/tester.css** — стили панели, полей, оверлеев (`.tester-regex-err-pos` для подсветки ошибок), выпадающего списка флагов (подсказка .tester-flags-hint), подсветки совпадений (full match и группы 1–60), спиннера, Match Information, **хедера блока совпадений и строки `.tester-selection-stats`**.

- **index.html:** секция `#tester.tester-section` между Визуализатором и Историей; ссылка «Тестер» в навигации; подключён `tools/tester/css/tester.css`.
- **main.js:** импорт и вызов `initTester()` при загрузке DOM.
- **tools/converter/app.js:** в `initHeaderNav()` добавлена секция `#tester` в IntersectionObserver; кнопка «Сбросить» вызывает `resetTesterPanel()`.

Истории у Тестера нет; сброс очищает поля и флаги, сбрасывает результат.

## Подсветка совпадений и групп

- **Цвета:** полное совпадение — основной цвет сайта (`.tester-hl-full`); группы 1–9 — фиксированные цвета (зелёный, жёлтый, фиолетовый и т.д.); группы 10–60 — запас из 51 оттенка по HSL (`.tester-hl-g10` … `.tester-hl-g60`), чтобы у каждой группы был свой цвет. Для всех классов подсветки используется только вертикальный отступ (`padding` по вертикали без горизонтального), чтобы цветной фон не «наезжал» на соседние символы и каретка оставалась визуально сразу после последней подсвеченной буквы.
- **Перекрытия:** при нескольких совпадениях сегменты от разных совпадений могут перекрываться по позициям. При построении HTML подсветки каждый символ рисуется не более чем одним сегментом: более поздний по позиции обрезается по текущей позиции вывода, чтобы подсветка не сливалась в один сплошной блок.

## Тесты

- **tests/tester-test.mjs** — тесты без DOM (Node), **69 тестов**: runMatch (базовая логика, флаги g/m/i/s/u/a), buildFlagsString (g,m,u по умолчанию; пользователь снял u → gm; a без u), applyExtendedFlag (x), референсные паттерны, \b с кириллицей, флаг a (ascii), длинный и многострочный текст; **ошибки паттерна:** лишняя `)`, ведущий и **конечный** `|`, **пустая альтернация `||`**, **лишняя `}`** (runMatch и validatePatternForUI), валидный квантификатор `{2}` не считается ошибкой; группы захвата и indices; эмуляция Python (ленивые `[\s\S]*`/`[\s\S]+` при g); **validatePatternForUI:** пустой паттерн, незакрытая `(`, валидный паттерн, ведущий и конечный `|`, `||`, лишняя `}` и `||`, валидный `{2,5}`. Запуск: `node tests/run-tests.mjs` или `node tests/tester-test.mjs`.
- **tests/test.html** — вкладка «Тестер»: браузерные тесты с cache-bust импортов (`?v=…`). Тесты: runMatch, флаги, buildFlagsString, extended, референс, \b с кириллицей, нагруженный текст; **ошибки:** лишняя `)`, ведущий и **конечный** `|`, **`||`**, **лишняя `}`**; **validatePatternForUI:** пустой, незакрытая `(`, валидный, лишняя `}` и `||`, валидный квантификатор; группы, indices, эмуляция Python; **TRUE/FALSE helper:** несколько тестов проверяют `filterMatchesByFalse` (пересекающиеся совпадения FALSE исключают TRUE, непересекающиеся не влияют, пустой FALSE не меняет результат). Кнопка «Запустить тесты Тестер», статистика, Export, Копировать логи/ошибки. В блоке «Проверка UI» описаны ручные проверки панели, включая работу строки статистики выделения.
- **tests/run-tests.mjs** — при `--browser` или `--browser-tester` запускаются браузерные тесты вкладки «Тестер» (Playwright). Отдельный UI‑тест проверяет, что при выделении текста в `#tester-test-input` `#tester-selection-stats` становится видимым и показывает корректные значения, а при потере фокуса скрывается. Для браузера: `npx playwright install`.

## Контент

Пользовательские строки (подсказки, кнопки, сообщения) задаются в **index.html** (секция #tester) и **tools/tester/ui/testerUI.js** (блок «Совпадения», единое сообщение об ошибке regex «Неверное регулярное выражение, исправьте ошибку.» и сообщение при Worker/таймауте, тосты).
