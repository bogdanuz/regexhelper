# Спецификация визуализатора — RegexHelper

Подробное описание требований к инструменту «Визуализатор»: что делает, как работает, что должен делать. Референс: [regexper.com](https://regexper.com/).

**Дата создания:** 2026-02-17

---

## 1. Назначение

Инструмент для визуализации регулярных выражений в виде railroad-диаграмм. Пользователь вводит готовый regex и получает графическое представление его структуры. Полностью независимый инструмент (отдельная папка в `tools/visualizer/`), не связан напрямую с внутренним состоянием конструктора/конвертера: интеграция только через явные кнопки «В визуализатор».

---

## 2. Размещение и структура

### 2.1 Расположение в приложении

- **Отдельная секция** после `#tester` и перед `#history-section`.
- ID секции: `#visualizer`.
- Ширина: на всю ширину экрана (аналогично панели «Связанные триггеры»).
- Расстояние между секциями разных инструментов — больше, чем между секциями одного инструмента.

### 2.2 Высота и панель (без скроллбара)

- **Блок «область диаграммы + панель»** (#visualizer-diagram-block) не привязан к высоте окна: высота всей секции определяется реальной высотой диаграммы, страница прокручивается обычным скроллом.
- **До построения диаграммы:** высота области диаграммы адаптивна (min-height около 280px), чтобы сохранить компактное приветственное состояние.
- **После построения диаграммы:** класс has-diagram включает «полноразмерный» режим — область подстраивается под реальную высоту SVG без искусственных `vh`‑ограничений, удобна работа с длинными диаграммами.
- **Скроллбара нет:** область диаграммы с `overflow: hidden`; масштаб и сдвиг задаются через **transform** (translate + scale) на обёртке — поведение как в Miro/Figma.
- **Zoom:** диапазон 25%–300%; кнопки −/+ (зум к центру); подсказка о Ctrl+колёсико (зум к курсору).
- При первой отрисовке: **fit to view** — диаграмма вписывается **по ширине** доступной области (масштаб не больше 100%), центрируется по горизонтали; высота диаграммы может быть больше окна браузера.

### 2.3 Навигация

- Клик по «Визуализатор» в header → smooth scroll к `#visualizer`.
- При скролле к секции визуализатора ссылка «Визуализатор» подсвечивается как активная (подчёркивание, как у «Конструктор»).

### 2.4 Раскрытие/сворачивание

- Кнопка «Свернуть/развернуть» **не требуется**.

## 3. Поле ввода regex

### 3.1 Поведение

- **Независимое** поле ввода — не синхронизируется автоматически с панелью результата конструктора; данные передаются только по нажатию кнопок «В визуализатор».
- Полностью редактируемое textarea; пользователь вставляет regex любым способом (Ctrl+V, кнопка, ввод с клавиатуры).
- **Высота поля:** без ограничения по максимуму; пользователь может раскрывать поле вручную (resize: vertical) по своему усмотрению.

### 3.2 Визуализация

- Только **по кнопке** «Визуализировать»; автовизуализация при каждом изменении поля не требуется.
-- Пользователь вставляет regex обычными средствами (Ctrl+V, контекстное меню браузера); отдельная кнопка «Вставить из буфера» не требуется.

## 4. Диаграмма (railroad diagram)

### 4.1 Референс

- Визуальная совместимость с [regexper.com](https://regexper.com/) **обязательна**.
- Референс по элементам и чтению: [regexper.com/documentation.html](https://regexper.com/documentation.html).

### 4.2 Элементы диаграммы (по Regexper)

- **Literals** — литералы (точное совпадение текста); светлые боксы с содержимым в кавычках.
- **Escape sequences** — escape-последовательности; отдельный цвет (зелёный в Regexper), описание типа символов.
- **Any character** — «любой символ», аналогично escape.
- **Character sets** — наборы символов: «One of» / «None of».
- **Subexpressions** — подвыражения с пунктирной рамкой; захватываемые группы — номер группы; lookahead/lookbehind — подписи.
- **Alternation** — альтернация, ветвление путей.
- **Quantifiers** — квантификаторы: zero-or-more, required, optional, range; подписи greedy / non-greedy.

### 4.3 Визуальный стиль

- Семантика и разметка как в Regexper (линии, скругления, стрелки, labels для greedy/non-greedy).
- Поле вывода диаграммы — белое, скруглённое, без отдельной рамки; группы — пунктирная рамка; линии и блоки с контрастной палитрой (regexper-overrides.css), без сплошной чёрной заливки у соединительных path.
- **Подзаголовок панели:** «Введите регулярное выражение и нажмите «Визуализировать» для построения диаграммы.»
- **До построения:** тёмный приветственный экран с подсказкой. **Во время построения (загрузка):** сразу показываются белое поле диаграммы, по центру — анимация загрузки (три пульсирующие точки) и панель экспорта/зума внизу (без мигания). **После построения:** диаграмма на белом фоне, панель остаётся на месте.
- Отступы: увеличенный padding области (36px) и патч в regexper.js (padding 10→16, 5→8) дают «охранные поля» между элементами, без наложения.
- Цвета — под палитру сайта RegexHelper (литералы, escape, anchor, repeat, группы, линии); элементы не сливаются с фоном.

### 4.4 Пан (перемещение)

- **ЛКМ + перетаскивание** в области диаграммы меняет сдвиг (panX, panY); скроллбара нет, движение через transform.

### 4.5 Зум (без скроллбара)

- Масштаб и сдвиг задаются одним **transform** на обёртке: `translate(panX, panY) scale(zoom/100)` с `transform-origin: 0 0`. Область диаграммы с `overflow: hidden` — скроллбара нет.
- **Zoom 25%–300%:** кнопки «Уменьшить» и «Увеличить» — зум к центру вьюпорта; **Ctrl + колёсико мыши** — зум к точке под курсором (как в Miro/Figma). На кнопках — подсказка (title) о Ctrl+колёсико.
- **Fit to view:** при первой отрисовке вызывается `applyFitToView()`: размеры SVG через `getBBox()` или `viewBox`, к размерам добавляется padding области (36px × 2); масштаб **вписывает диаграмму по ширине области просмотра** (не больше 100%), panX/panY центрируют по доступной области. Обёртка имеет размер по контенту (min-width/min-height: 0), поэтому маленькие и большие диаграммы центрируются одинаково по ширине.
- При генерации новой диаграммы зум и пан сбрасываются, затем применяется fit to view.

### 4.6 Вкладки диаграмм

- У визуализатора есть строка вкладок; каждая вкладка соответствует одной диаграмме.
- При первом построении диаграммы в сессии используется уже существующая пустая стартовая вкладка «Новая диаграмма» (она переименовывается и получает содержимое вместо создания дубликата).
- При последующих визуализациях из поля ввода или при вызове из других инструментов (кнопка «В визуализатор») создаётся **новая вкладка**, предыдущие диаграммы остаются доступными.
- Заголовок вкладки показывает начало регулярного выражения (обрезанное и «очищенное» для удобства чтения).
- Вкладки можно закрывать по одной; есть кнопка сброса панели визуализатора, которая очищает все вкладки и оставляет одну пустую стартовую.
- Справа от вкладок находится компактная кнопка «+» для добавления новой пустой вкладки без ввода regex.
- Максимальное количество вкладок ограничено (по умолчанию 20); при попытке создать больше показывается уведомление.

## 5. Экспорт

### 5.1 Форматы и UI

- **Одна кнопка «Скачать»:** по клику раскрывается выпадающее меню вправо по горизонтали с пунктами **SVG** и **PNG** (все три элемента в одну линию, равные отступы). Меню открывается плавно (transition opacity); без дополнительной обводки контейнера — только кнопки.
- Форматы **SVG** и **PNG** — оба; логика экспорта без изменений (SVG/PNG из текущего SVG с встроенными стилями).

### 5.2 Имя файла

- Фиксированный формат: `diagram_DD-MM-YYYY_HH-mm.svg` (локальное время, без часового пояса).
- Пример: `diagram_17-02-2026_14-30.svg`.

## 6. Техническая реализация

### 6.1 Источник логики диаграмм

- Использовать **готовую библиотеку** или форк с открытым кодом (javallone/regexper, bubkoo/regexper, AkatQuas/regexper-ng).
- Лицензия: только бесплатная (MIT, Apache и т.п.).
- Цель: визуальная совместимость с regexper.com.

### 6.2 Поддерживаемый синтаксис

- Как у Regexper: JavaScript RegExp и всё, что Regexper поддерживает (флаги, группы, lookahead/lookbehind и т.д.).

### 6.3 Обработка ошибок

- При невалидном regex: **toast-уведомление** с текстом ошибки.
- Не прерывать работу приложения; пользователь может продолжить ввод и попробовать снова.
